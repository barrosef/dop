# Context and knowledge

> **Status:** Approved for review · **Date:** 2026-08-29 · **Project:** the DOP platform
>
> **Answers:** what the agent knows before starting, where that knowledge lives, how it is
> assembled per demand and how it grows.
>
> **Does not answer:** the format of the demand's spec (SP-4's core, pending); physical
> persistence (SP-3).

The base decision: [ADR-0009](../../adr/0009-context-as-subsystem.md); it leans on
[ADR-0006](../../adr/0006-demand-as-event-log.md) and
[ADR-0010](../../adr/0010-multi-agent-per-demand.md).

## 1. The project's knowledge base

A versioned entity, per project, in three layers:

| Layer | Content | Who writes it |
|---|---|---|
| **Rules** | The conventions the agent obeys: branch flow, prohibitions, naming patterns, test policy | A human, from the cockpit; an agent's change to a rule is a commit behind a human gate |
| **The index** | The repositories' map: modules, responsibilities, how to build, how to test, ports and services | Generated by the agent, committed to `index/`; refreshed on a merge event |
| **Memory** | Findings from past demands, lessons, the customer's ADRs, forensic readings | The thread, committing into `memory/` at the end of the demand (P-41) |

Everything in the table is a FILE in the project's root repository ([ADR-0028](../../adr/0028-project-knowledge-as-a-git-repository.md)):
`rules/`, `index/`, `memory/`, and `demand/<id>/` for what belongs to one demand. Who writes
is who commits; how a commit is attributed is [ADR-0003](../../adr/0003-organization-credential-human-authorship.md)'s.

## 2. Where it lives

**Text in git, bytes in the bucket.** The project's root repository holds every document
(ADR-0028), hosted by the platform, one per project, born with it; the `ObjectStore` (ADR-0001)
keeps what a repository is bad at — rendered diagrams, exports — referenced from the files.
Every sandbox of the project **clones the repository at `/project`, read-write**; sharing is
push/pull; every push is an event (ADR-0006). The `knowledge_artifacts` rows are an INDEX over
the repository — path, commit, embedding — not the storage of the text.

Two things that are easy to confuse, and must not be: the **shelf** (the clone — complete, on
disk, costs nothing until a file is opened) and the **package** (§3 — curated, budgeted, in
the prompt, paid for on every turn). The shelf is where the agent goes for what the package
left out.

## 3. The context package

Assembled by the orchestrator in the sandbox's `provision()`:

```
package = the demand's spec
        + the project's rules
        + the index OF THE DEMAND'S REPOSITORIES (not of the whole project)
        + the relevant memories (selected by their relation to the demand)
        + the findings already published on the demand (on a resume)
```

A size discipline: the package grows with the **demand**, not with the project. What did not
fit is on the shelf — the agent opens it with the one tool it has (`run_command`):
`cat /project/index/<repo>.md`, `grep -r … /project/memory/`. There is no `search_memory` and
no `read_index` tool, and there must not be: every named tool is a permanent cost in every
turn's prefix (ADR-0023, `tools.go`), and the shelf makes them a `cat`.

**Two engineering requirements (ADR-0012):**

- **Deterministic serialization.** The package goes into the prompt's cached prefix: a stable
  order, no timestamps, no volatile IDs. A changed byte invalidates the cache from there on —
  assembling it "any old way" burns ~90% of a discount in silence.
- **Measurement at assembly.** The package's size is measured by token counting (a free
  endpoint) and emitted as an event; above the project's ceiling, an alert — the "it grows
  with the demand" discipline has a number, not an impression.

## 4. The cycle

```
provision → the agent works (it reads the package, queries for more)
          → the subagents publish findings (ADR-0010)
          → the demand closes → findings and lessons → the memory layer
          → a merge into main → an event → the index regenerates the affected part
```

Today's forensic reading is tomorrow's demand's context. Context is a cycle, not a file.

## 5. Risks

| # | |
|---|---|
| R-1 | Memory grows with no curation and becomes noise — relevance when assembling the package is the orchestrator's work, with periodic pruning |
| R-2 | An outdated index is worse than a missing index (it lies with confidence) — which is why the update is on a merge event, never on a cron |
| R-3 | The memory's content includes third-party text (cards, logs) — it enters the package as untrusted, by the substrate's security rule |
